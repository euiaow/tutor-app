# Экзаменационный Радар — ТЗ и план реализации

## Идея в одном абзаце

Студент открывает личный кабинет и видит не просто список тем — он видит ответ на вопрос "я успею?". Блок обратного отсчёта показывает сколько дней до экзамена, текущий темп прохождения тем и нужный темп для достижения цели. Умный комментарий на основе реальных данных говорит прямо: "всё идёт по плану" или "нужно ускориться — вот что делать на этой неделе". Учитель один раз загружает шаблон тем под тип экзамена и целевой балл, потом при необходимости редактирует под конкретного ученика. Вся аналитика строится автоматически из данных которые учитель уже вносит.

---

## Онбординг: кто что заполняет

### Учитель (при создании/редактировании ученика)
- Предмет (математика, русский язык, физика…)
- Тип экзамена (ЕГЭ / ОГЭ / школьный / другой)

На основе предмета + типа система подбирает шаблон тем. Учитель может отредактировать список под конкретного ученика.

### Ученик (в личном кабинете, блок "Моя цель")
- Целевой балл (число или слайдер)
- Примерная дата экзамена (datepicker)

Логика: учитель знает предмет и формат экзамена, ученик знает свою цель и дату. Разделение ответственности естественное. Блок "Моя цель" показывается только если учитель уже заполнил предмет и тип экзамена — иначе шаблон тем не подобрать. Если ученик ещё не заполнил цель — Радар показывает заглушку с призывом заполнить.

## Шаблоны тем (предзагруженные данные)

Структура одного шаблона:
```
{
  subject: "математика",
  examType: "ЕГЭ",
  scoreBands: [
    { minScore: 60, maxScore: 74, requiredTopics: ["алгебра_базовая", ...] },
    { minScore: 75, maxScore: 89, requiredTopics: ["алгебра_базовая", "производная", ...] },
    { minScore: 90, maxScore: 100, requiredTopics: [...все темы...] }
  ]
}
```

Шаблоны хранятся в Firestore в отдельной коллекции `curriculumTemplates`. Заполняются вручную один раз (офлайн задача, не автоматизируется). При назначении шаблона ученику — копия создаётся в его документе `students/{id}/curriculum` чтобы учитель мог редактировать без влияния на шаблон и других учеников.

## Логика расчёта (фронтенд / Cloud Function)

Входные данные:
- `examDate` — дата экзамена
- `targetScore` — целевой балл
- `requiredTopics` — список тем нужных для этого балла (из шаблона)
- `completedTopics` — темы отмеченные учителем как пройденные
- `lessonHistory` — даты уроков

Вычисляемые метрики:
```
daysLeft = examDate - today
weeksLeft = daysLeft / 7
topicsLeft = requiredTopics.length - completedTopics.length
neededPace = topicsLeft / weeksLeft  // тем в неделю

// Реальный темп: темы за последние 4 недели / 4
recentTopics = completedTopics.filter(t => t.completedAt > 4 weeks ago)
currentPace = recentTopics.length / 4

paceRatio = currentPace / neededPace
// < 0.7 → красный, 0.7–1.1 → жёлтый, > 1.1 → зелёный
```

## Умный комментарий: два варианта реализации

### Вариант А — Шаблонный (без LLM, быстро)

Набор заготовленных строк с подстановкой переменных:

```js
if (paceRatio > 1.1) {
  "Отличный темп! Если продолжишь так же — закроешь все темы за {weeksToFinish} нед. до экзамена. Останется время на повторение."
} else if (paceRatio > 0.7) {
  "Небольшое отставание. За последние 2 недели пройдено {recentCount} тем при нужных {neededCount}. Чтобы выйти на {targetScore} баллов, держи темп {neededPace} темы в неделю."
} else {
  "Нужно ускориться. До экзамена {weeksLeft} нед., осталось {topicsLeft} тем — текущий темп не позволяет закрыть их вовремя. В ближайшие 2-3 недели нужен темп {catchUpPace} темы в неделю."
}
```

Плюсы: работает без API, мгновенно, предсказуемо.

### Вариант Б — LLM-генерация (Claude API)

Передаём в промпт метрики и получаем живой текст:

```
Ты — наставник школьника который готовится к ЕГЭ по математике.
Данные: дней до экзамена: {daysLeft}, цель: {targetScore} баллов,
тем пройдено: {completed} из {required}, темп: {currentPace}/нед, нужен: {neededPace}/нед.
Напиши короткий (2-3 предложения) мотивирующий комментарий о текущем прогрессе.
Конкретно, без воды. Тон — честный наставник, не чирлидер.
```

Плюсы: живой текст, адаптируется к нюансам ситуации, хорошее место чтобы поиграться с LLM.
Минусы: задержка, расход токенов, нужен API ключ на фронте или Cloud Function.

**Рекомендация:** начать с Вариантом А, добавить Вариант Б как опцию (кнопка "Объясни подробнее").

## Структура данных в Firestore

```
students/{studentId}
  examDate: Timestamp
  targetScore: number
  subject: string
  examType: "ЕГЭ" | "ОГЭ" | "школьный"

students/{studentId}/curriculum (subcollection или поле)
  topics: [
    { id: "derivative", title: "Производная", completedAt: Timestamp | null },
    { id: "integral",   title: "Интеграл",    completedAt: Timestamp | null },
    ...
  ]

curriculumTemplates/{templateId}
  subject: string
  examType: string
  scoreBands: [{ minScore, maxScore, topicIds[] }]
  topics: [{ id, title }]
```

## Поэтапный план реализации

### Этап 0 — Данные (офлайн, ручная работа)
Составить шаблоны тем для 2-3 популярных предметов (математика ЕГЭ, русский язык ЕГЭ). Загрузить в Firestore вручную или скриптом. Это разовая задача, не блокирует разработку — можно начать с одним тестовым шаблоном.

### Этап 1 — Расширить данные ученика
- Учитель: добавить поля subject, examType в форму редактирования ученика
- Ученик: добавить блок "Моя цель" в личный кабинет с полями targetScore и examDate; сохраняется в Firestore в документ ученика через unauthenticated callable (как остальные студенческие действия)

### Этап 2 — Назначение шаблона
При выборе subject + examType + targetScore — автоматически подбирать шаблон из `curriculumTemplates` и копировать список тем в документ ученика. Учитель может редактировать список.

### Этап 3 — Блок Радара на студенческом дашборде
Компонент `ExamRadar.jsx` который:
- Читает данные ученика (examDate, targetScore, topics)
- Вычисляет все метрики на клиенте
- Рендерит блок с прогресс-баром, статусом и комментарием (Вариант А)

### Этап 4 — LLM комментарий (опционально)
Cloud Function `generateExamComment` принимает метрики, вызывает Claude API, возвращает текст. Вызывается по кнопке, не автоматически.

## Подводные камни

**1. Актуальность шаблонов**
Кодификаторы ЕГЭ/ОГЭ меняются каждый год. Шаблоны нужно будет обновлять вручную — это операционная нагрузка. Решение: версионировать шаблоны (`year: 2025`) и показывать учителю предупреждение если шаблон старый.

**2. Темп считается по урокам, а не по самостоятельной работе**
Если ученик болел 2 недели — темп покажет красный статус хотя это форс-мажор. Решение: считать темп за последние 4 недели, не 2 — сглаживает выбросы. Или добавить возможность учителю отмечать "пропуск по уважительной причине".

**3. Разные предметы — разная структура тем**
Математика ЕГЭ имеет чёткие темы. Литература или история — гораздо менее формализованы. Решение: начинать только с точных предметов (математика, физика, химия, русский язык) где структура тем устоялась.

**4. Мотивационный эффект может работать в обе стороны**
Если ученик видит красный статус — это может демотивировать, особенно тревожных детей. Решение: формулировки комментариев тестировать на реальных учениках, избегать алармистского тона даже при отставании.

**5. LLM комментарий — latency и стоимость**
Если вызывать Claude API на каждую загрузку страницы — это задержка и расход токенов. Решение: кэшировать комментарий на 24 часа в Firestore, обновлять только если метрики значительно изменились.

**6. Данные могут быть неполными**
Если учитель не отметил пройденные темы несколько недель — темп будет занижен и покажет ложную тревогу. Решение: показывать дату последнего обновления прогресса и мягко напоминать учителю обновить данные после урока.
